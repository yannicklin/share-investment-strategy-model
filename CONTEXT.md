## 📊 Core Domain Concepts

### Strategy & Analysis Terminology

| Term | Definition | Example |
|------|-----------|---------|
| **Strategy** | Trading rule or algorithm | "Buy undervalued large-caps, hold 6 months" |
| **Backtest** | Historical simulation of strategy | 10 years of ASX daily data, fees included |
| **Signal** | BUY/SELL/HOLD recommendation | Generated by model at each decision point |
| **Model** | AI algorithm for prediction | Random Forest, LSTM, Prophet, CatBoost, NGBoost |
| **Consensus** | Multi-model voting outcome | 3/5 models vote BUY → signal is BUY |
| **Equity Curve** | Realized account value over time | Starting $100k → ending $250k after 10 years |
| **Win Rate** | % of trades with positive return | 55% (standard metric for strategy quality) |
| **Hurdle Rate** | Minimum acceptable return | 8% annual (fees + tax + risk buffer) |
| **Drawdown** | Max peak-to-trough loss | -25% (largest loss from high water mark) |
| **Sharpe Ratio** | Risk-adjusted return | Higher = better risk/reward tradeoff |

### Market Terminology

| Term | Definition | Example |
|------|-----------|---------|
| **Index** | Collection of stocks | ASX 50, ASX 200, S&P 500 |
| **Market** | Stock exchange | ASX (Australia), USA (NYSE/NASDAQ) |
| **Ticker** | Stock symbol | CBA, AAPL, 0050.TW |
| **Period** | Backtesting timeframe | 1 year, 5 years, 10 years |
| **Holding Period** | How long to hold each trade | 1 day, 30 days, 6 months, 1 year |
| **Lookback Window** | Historical data for feature calculation | 20 days for moving average |
| **Warmup Period** | Data before backtest for indicator priming | 90 days before test start |

## 💰 Financial Constraints (Non-Negotiable)

### The "Big Three" Friction Points
1. **Brokerage Fees**: Every trade costs money
   - ASX: ~$10-30 per trade (varies by broker)
   - USA: ~$0-10 per trade (many offer free trading)
   - Applied at entry and exit (buy + sell)

2. **Tax Implications**: Net profit is after tax
   - Capital gains tax (CGT) on realized profits
   - CGT discount (50%) for holdings > 12 months in Australia
   - Tax-aware hurdle rate calculation

3. **Market Slippage**: Orders don't execute at exact price
   - Bid-ask spread (cost to enter/exit)
   - Liquidity impact (larger orders move the price)
   - Modeled as percentage of trade size (typically 0.1-0.5%)

### Realistic Accounting
- **No shortcuts**: Every model backtest accounts for all three
- **Settlement delays**: T+2 for ASX/TWN, T+1 for USA
- **Trading days**: Exclude weekends + holidays in calculations
- **Warmup data**: Fetch 90 days before backtest start to prime indicators

## 🎯 Model Ecosystem

### Supported Algorithms

| Model | Type | Strength | Use Case |
|-------|------|----------|----------|
| **Random Forest** | Ensemble tree | Robust, handles non-linear patterns | General purpose |
| **LSTM** | Neural network (sequence) | Captures temporal dependencies | Trend following |
| **Prophet** | Time series | Explicit trend/seasonality | Seasonal strategies |
| **CatBoost** | Gradient boosting | Handles categorical features well | Mixed data types |
| **NGBoost** | Probabilistic boosting | Quantified uncertainty | Risk-aware trading |

### Consensus Logic
- **Voting**: Each model predicts BUY/SELL/HOLD
- **Count**: Tally votes (e.g., 3 BUY, 1 SELL, 1 HOLD)
- **Threshold**: Require >50% consensus (e.g., 3/5 = BUY)
- **Confidence**: Score = majority_count / total_models (0.6 = 60% confidence)

**Why?** Single models can overfit. Ensemble reduces bias and improves robustness.

## 📈 Key Workflows

### Strategy Backtesting (Primary Workflow)
1. Define strategy parameters (entry rules, exit rules, holding period)
2. Fetch historical data (with 90-day warmup)
3. Engineer features (RSI, MACD, moving averages, etc.)
4. Train model on historical data
5. Run backtest simulation (apply strategy rules, track P&L)
6. Calculate metrics (ROI, win rate, sharpe ratio, drawdown)
7. Compare vs baseline (buy-and-hold)

### Model Training Pipeline
1. Fetch 2+ years historical data
2. Engineer features (standard technical indicators)
3. Split: training (80%), testing (20%)
4. Train 5 models: Random Forest, LSTM, Prophet, CatBoost, NGBoost
5. Validate each model on holdout test set
6. Persist best model to `data/models/`
7. Log performance metrics for comparison

### Performance Comparison (Secondary Workflow)
1. **Models Comparison**: Same strategy, different algorithms
   - Q: Which model is best for this strategy?
2. **Strategy Comparison**: Different holding periods, same model
   - Q: Is 30-day holding better than 6-month?
3. **Index Comparison**: Same strategy across different indices
   - Q: Does this work on ASX 50, ASX 200, and USA?

## 🔒 Data Integrity Rules

### Input Validation
- Ticker must exist in market (fetch via yfinance/Alpaca)
- Period must be >= 1 year (insufficient data otherwise)
- Holding period must be >= 1 trading day
- Date range must not exceed available data

### Output Validation
- Equity curve: Must be monotonic (accounting for losses)
- Win rate: Must be 0-100% (inclusive)
- Sharpe ratio: Must have valid denominator (no division by zero)
- Drawdown: Must be >= 0 (by definition, can't be positive)

### Feature Engineering Checks
- Array shapes must match before scaling (no broadcasting errors)
- NaN/Inf checks before model training
- Lookback window must not exceed available data
- Price data must use `Close` column (auto_adjust=True)

## 📚 Performance Metrics

### Standard Metrics (All Strategies)

| Metric | Definition | Good Value | Example |
|--------|-----------|-----------|---------|
| **ROI** | Total return on investment | > 8% annualized | 45% over 5 years |
| **Win Rate** | % of trades with profit | > 50% | 55% (55 winning, 45 losing) |
| **Sharpe Ratio** | Risk-adjusted return | > 1.0 | 1.25 (good risk/reward) |
| **Max Drawdown** | Largest peak-to-trough loss | < 25% | -18% during 2020 |
| **Annual Return** | Average yearly profit | > Hurdle Rate | 8% per year |

### Comparison Metrics
- **Alpha**: Excess return vs market index
- **Beta**: Volatility vs market (1.0 = market, <1.0 = less volatile)
- **Correlation**: How strategy moves with index

## 🛠️ Common Patterns

### Adding a New Market
1. Define market in `core/config.py` (calendar, suffix format)
2. Create market-specific data helper in `core/data_helpers/`
3. Test model training on that market's tickers
4. Add to UI market selector dropdown
5. Document market-specific constraints (trading hours, settlement rules)

### Adding a New AI Model
1. Implement in `core/model_builder.py` (factory pattern)
2. Inherit base model interface
3. Test with `/tdd` (write test first)
4. Backtest against 2+ years historical data
5. Verify it wins against baseline in at least one scenario
6. Add to consensus voting logic

### Debugging a Bad Backtest
1. Check data integrity (no NaN, correct date range)
2. Verify fee calculation (compare manual vs model)
3. Inspect feature engineering (are indicators calculated correctly?)
4. Review signal generation (does entry/exit logic match spec?)
5. Run `/diagnosing-bugs` skill for structured troubleshooting
